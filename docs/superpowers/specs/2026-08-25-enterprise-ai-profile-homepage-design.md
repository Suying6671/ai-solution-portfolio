# 万舒畅企业 AI 个人主页重做设计

## 1. 项目目标

本次只重做首页，不新增独立案例详情页。页面不是“网页版 PDF 简历”，而是一份面向招聘方的个人 Profile 与企业 AI 项目作品集。

首页需要让招聘方快速形成以下判断：万舒畅能够进入真实企业业务场景，完成需求发现、问题拆解、AI 方案设计、Agent / Workflow / POC 搭建、客户交付、质量评测，并把单点项目沉淀为可复用能力。

内容以《万舒畅_企业AI解决方案个人主页_网页需求文档.md》为事实与文案来源。文档中的建议被视为内容 brief，而不是必须逐字执行的网页生成指令。已在设计讨论中确认的选择优先于文档原建议。

## 2. 已确认范围

- 只保留一个长首页。
- 四个代表项目均在首页展示。
- 点击“查看完整案例”后，在当前项目区域内联展开案例，不跳转页面。
- 同一时间只展开一个案例；再次点击或点击“收起”关闭。
- 不新增后台、数据库、表单提交或外部内容接口。
- 保留现有 React / Vinext 技术栈与静态内容组织方式。
- 使用现有 PDF 简历下载资源。
- 首屏人物照片换成用户指定的 `/Users/leslie/Desktop/微信图片_2026-08-21_185040_766.jpg`，正式开发时复制为站内优化后的公开资源。

## 3. 设计方向

### 3.1 参考风格

视觉与排版以 Linea Prompt 为主要参考，而不是简单套用蓝灰色：

- 浅冰蓝灰背景与极淡网格。
- 近黑蓝文字和深色重点区。
- 靛蓝作为按钮、选中态和少量强调色。
- 薄荷青用于核心成果数字和可信状态。
- 悬浮白色导航、半透明界面卡片、细边框和柔和阴影。
- 大字号、紧行高、明显留白，以及产品界面式信息容器。
- 局部深色章节形成节奏变化。
- 动效克制，不使用赛博霓虹、夸张 3D、滚动劫持或持续漂浮动画。

本项目借鉴视觉语言与页面节奏，不复制 Linea Prompt 的品牌标识、文案或产品界面。

### 3.2 色彩与字体

- 页面背景：`#EDF3F8`
- 主文字 / 深色区：`#0D1420`
- 主按钮：`#32389F`
- 选中态：`#5157D8`
- 成果强调：`#94E2D5`
- 次级文字：约 `#687587`
- 卡片：半透明白色配低对比边框
- 中文正文：系统无衬线字体，优先 `PingFang SC`
- 英文标签与编号：等宽字体，优先 `IBM Plex Mono`，缺失时使用系统等宽字体

### 3.3 动效

- 卡片 hover 仅做 2–3px 上移、阴影增强或边框颜色变化。
- 按钮和案例展开使用 160–220ms 过渡。
- 案例展开后自动将展开区滚动到舒适阅读位置，但不强制锁定滚动。
- 尊重 `prefers-reduced-motion`，关闭非必要位移和动画。

## 4. 首页信息架构

首页顺序如下：

1. 悬浮导航
2. 首屏个人定位
3. 首屏成果条
4. 代表项目与页内案例展开
5. 跨项目企业 AI 能力

## 5. 各模块设计

### 5.1 悬浮导航

使用 Linea Prompt 风格的圆角半透明白色导航，宽度小于页面内容区。

导航项：

- 代表项目
- 搭建方法
- 工作经历
- 联系
- 下载简历

桌面端完整显示；移动端收为菜单按钮。导航锚点滚动需考虑吸顶偏移。

### 5.2 首屏个人定位

桌面端为左文案、右界面式人物卡的双栏结构。

主标题固定为：

> 把复杂业务变成可交付的 AI 能力

桌面端尽量保持单行，不使用逗号。窄屏允许自然换行。

英文小字：

> Turning complex business needs into deployable AI capabilities.

职业定位：

> 企业 AI 解决方案｜AI 产品｜FDE

中文介绍：

> 将复杂、模糊的企业业务需求，转化为可落地、可交付、可复制的 AI 产品与解决方案。

补充说明：

> 覆盖需求发现、Agent / Workflow、POC、客户交付与规模化复用。

CTA：查看代表项目、下载简历、联系我。

右侧不是普通大头像，而是一个 “AI Solution Profile” 界面卡。用户指定照片嵌入卡片，并搭配姓名、职业定位、能力标签和代表项目条目，使人物与“能做出 AI 系统”的信息同时出现。

照片裁切以人物面部与上半身为中心，保留少量城市和喷泉背景，不做过度磨皮或生成式修改。

### 5.3 首屏成果条

首屏底部使用近黑蓝深色横条，固定展示三个横向成果卡：

- 7 个核心 AI Skill
- 5 个独立客户 AI 实例
- 累计节省 77+ 小时人工

数字使用薄荷青。桌面与平板保持三列；手机窄屏可纵向排列。

### 5.4 代表项目

采用已确认的 B 方案：一张深色旗舰横幅，下方三张横向精选项目卡。

三张精选卡在桌面与常规平板宽度保持横向三列，只在真正的手机窄屏（约 560px 以下）切为纵向。

旗舰项目名称统一为：

> 广告投放素材洞察数字员工

旗舰横幅展示：

- 7 个核心 AI Skill
- 5 个独立客户实例
- 11 次完整业务流程真实运行
- 单次交付人工投入从 1 个工作日缩短至 1 小时以内
- 累计节省 77+ 小时人工

三张精选卡的成果必须说明指标含义，禁止只写孤立数字：

- AI 品牌舆情与品牌洞察解决方案：已交付 6 期舆情月报；客户平均内容采纳率约 98%。
- 多语言翻译与质量评估 Agent：完成 80 集真实短剧验证；客户质量评分 90+；客户内部翻译团队评分 80+。
- AI 媒介流量洞察平台：约 15 分钟生成 1 份媒介流量洞察报告。

### 5.5 案例页内展开

点击任一项目的“查看完整案例”后，在四张项目卡下方出现一个横跨整栏的展开区域。

展开区域依次包含：

1. 项目概览
2. 业务问题
3. 需求发现与关键判断
4. 解决方案
5. 系统架构 / Workflow
6. 我具体做了什么
7. 项目结果
8. 项目复盘与能力沉淀

项目切换时复用同一个展开容器并替换内容，避免页面同时出现四个超长案例。展开内容由静态数据驱动。

每个案例至少有一张使用 HTML/CSS 绘制的流程或架构图。没有真实 Badcase 时不编造翻译示例或客户数据。

### 5.6 跨项目企业 AI 能力

模块标题：

> 从客户需求到 AI 落地

四张横向能力卡分别由不同项目提供证据，避免整段成为旗舰项目的延伸：

- 业务洞察：品牌舆情与洞察项目，证明客户沟通、流程拆解和商业价值发现。
- 方案设计：翻译质量 Agent，证明上下文、Workflow、Evaluation 和 Human-in-the-loop。
- 快速搭建：媒介流量洞察平台，证明专家方法抽象、PRD、Prompt、UI 与客户测试。
- 交付与规模化：广告投放素材洞察数字员工，证明配置化、多客户部署、质量关卡与自主使用。

### 5.7 通用 AI 产品搭建方法

使用深色流程区展示一套跨项目通用的方法，而不是只展示某个案例的 YAML 或 Skill：

> 客户沟通 → 业务流程拆解 → AI 场景发现 → 方案设计 → POC / Demo → 评测与交付 → 复用与规模化

随后用四个不同项目分别证明方法的不同部分：

- 品牌舆情：企业数据、客户定制、报告交付与增值机会。

## 6. 组件与数据结构

建议拆分以下组件：

- `SiteHeader`：导航与移动菜单
- `Hero`：首屏文案、人物界面卡和 CTA
- `ProofStrip`：三个首屏成果
- `ProjectShowcase`：旗舰横幅、三张项目卡和选择状态
- `ExpandedCaseStudy`：统一案例展开容器
- `CapabilityGrid`：四类跨项目能力
- `MethodFlow`：通用 AI 落地链路与跨项目证据
- `ClientDelivery`：9 步 Client-facing 链路
- `ExperienceTimeline`：工作与教育
- `Toolkit`：分层技术和产品能力
- `OtherProjects`：两个轻量项目卡
- `ContactPanel`：联系与简历下载

静态内容集中在 `content/profile.ts` 或拆分后的同目录模块。项目数据增加以下字段：

- 首页摘要
- 明确指标及其单位 / 含义
- 业务问题
- 关键判断
- 解决方案
- Workflow 节点
- 个人职责
- 项目结果
- 复盘

只有项目展开交互和移动菜单需要客户端状态。默认所有案例折叠；点击项目后设置 `activeProjectId`，再次点击同一项目则清空。

## 7. 异常与降级

- 人物照片加载失败时显示姓名首字母与纯色背景，不出现破图图标。
- 简历资源缺失时隐藏下载入口，避免死链。
- 未提供联系方式的渠道不渲染。
- JavaScript 不可用时仍展示四个项目摘要与核心成果；案例详情可通过默认展开旗舰案例作为渐进降级方案。
- 超长中文、英文技术名词和数字必须允许合理换行，不得造成横向溢出。
- 流程图在移动端改为纵向节点，保持阅读顺序。

## 8. 响应式与可访问性

- 桌面宽度约 1180–1240px 内容区。
- 桌面首屏双栏，标题单行；移动端改为上下布局并允许标题换行。
- 三张精选项目卡在桌面和平板保持横向三列，约 560px 以下改为单列。
- 所有交互元素支持键盘操作与清晰的 focus 状态。
- 案例展开按钮使用真实 `button`，提供 `aria-expanded` 与 `aria-controls`。
- 色彩对比满足正文可读性要求；薄荷青只用于深色背景上的强调。
- 图片提供准确中文替代文本。

## 9. 验收与测试

### 内容测试

- 首页主标题、英文副标题、职业定位与 CTA 文案准确。
- 旗舰项目名称在所有位置统一为“广告投放素材洞察数字员工”。
- 所有成果数字带明确含义，不出现孤立的“6 期 · 98%”等表达。
- 不出现未验证技术能力、虚构客户案例或虚构 Badcase。

### 交互测试

- 四个项目均可展开、切换和收起。
- 同时只显示一个完整案例。
- 导航锚点、联系按钮和 PDF 下载可用。
- 移动菜单可打开、关闭并在选择导航后收起。

### 视觉测试

- 在桌面约 1440px、平板约 768px、手机约 390px 三种视口检查。
- 桌面和平板三张精选项目卡保持横向排列；手机才改为纵向。
- 检查标题换行、人物照片裁切、流程图方向、展开区域高度与页面横向溢出。
- 检查深色区、白色卡片和网格背景是否保持 Linea Prompt 风格而不过度模仿品牌。

### 工程验证

- `npm run lint`
- `npm run test:unit`
- `npm run build`
- 现有渲染 HTML 测试更新并通过
- 浏览器检查控制台无错误，页面无破图与死链
